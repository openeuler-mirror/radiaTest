# 工单管理规格

## 状态

有效(Active)。

## 目标

radiaTest 提供面向所有已登录用户的内部工单管理能力，用于提交需求和缺陷，并由管理员完成受理、分派和关闭。

## 领域模型

### 工单

- 工单使用从 `1` 开始递增且不复用的整数 ID。
- 类型固定为需求(`REQ`)和缺陷(`BUG`)。
- 两种类型使用相同字段和状态流；复现步骤、验收标准等内容直接写入正文。
- 标题和正文为必填纯文本，分别最多 120 和 10,000 字符。
- 不支持富文本和附件。
- 状态固定为待处理(`PENDING`)、已接受(`ACCEPTED`)、已拒绝(`REJECTED`)和已完成(`COMPLETED`)。
- 优先级固定为高(`HIGH`)、中(`MEDIUM`)和低(`LOW`)。
- 责任人引用一个现有 `ADMIN` 用户。
- 计划完成时间由管理员在接受时填写；实际完成时间在标记完成时由系统记录。
- 不单独记录接受时间或拒绝时间；`updated_at` 表示最后一次工单内容或处理字段变化。
- 已接受但未完成且超过计划完成时间的工单派生显示为“已逾期”，不新增状态。

状态只允许单向转换：

```text
PENDING -> ACCEPTED -> COMPLETED
        -> REJECTED
```

不支持撤回、退回、重新接受或重新打开。
不支持删除或软删除；误提交由管理员拒绝并填写理由。

### 工单评论

- 评论为必填纯文本，最多 5,000 字符。
- 评论保存作者和创建时间，提交后不可编辑或删除。
- 评论不改变工单状态。
- 评论按通知管理规格生成站内通知；详情页仍通过用户手动刷新读取最新评论。
- 评论不分页，按创建时间正序展示。
- 评论输入位于详情页底部；提交成功后重新读取详情，不自动滚动。

## 权限

- 所有已登录用户都可以提交并查看全部工单。
- 提交人只能在工单处于 `PENDING` 时编辑自己工单的标题和正文。
- `ADMIN` 不能修改工单标题和正文；需要补充或纠正时使用评论。
- 只有 `ADMIN` 可以接受、拒绝、完成工单，以及修改优先级、责任人和计划完成时间。
- 接受时必须同时填写优先级、责任人和晚于当前时间的计划完成时间。
- 责任人必须是现有且启用的 `ADMIN`；`TSE` 和 `TE` 不能被指派。
- 已禁用管理员保留历史关联，但不能被新指派或改派。
- 执行接受操作的管理员可以把自己设为责任人。
- 当前责任人被禁用后，工单继续显示其历史身份并保持原状态；`ADMIN` 可以手动改派给启用用户。
- 拒绝时必须填写最多 2,000 字符的纯文本理由正文。
- 拒绝接口由后端在理由正文前自动添加执行操作的管理员用户名；前端不提交或拼接用户名，
  数据库使用 `TEXT` 保存最终的 `[username] 理由正文`，不另设拒绝人字段。
- 所有已登录用户都可以查看评论；提交人、当前责任人和 `ADMIN` 可以发表评论。
- 工单改派后，原责任人不再拥有评论权限，但其历史评论保留。
- `REJECTED` 和 `COMPLETED` 状态仍允许原有参与人发表评论，评论不改变终态。
- 工单和评论操作不写入通用审计日志。

## 通知

- 工单评论、接受、改派、拒绝、完成和处理字段修改按
  [通知管理规格](0004-notification-management.md)生成站内通知。
- 工单通知不投递飞书；工单查看和处理只在 Web 中完成。
- 工单业务修改和站内通知在同一 PostgreSQL 事务中提交。

## 页面

### 工单管理

- 左侧导航在“测试任务”之后、“用户管理”之前提供所有用户可见的“工单管理”入口。
- `/tickets` 展示所有工单，页面提供“提交工单”按钮。
- “提交工单”只在工单管理页提供，不在全局顶部栏、概览页或其他业务页面重复展示。
- 提交弹窗只包含类型、标题和正文；类型默认选中 `REQ`，提交成功后跳转到新工单详情页。
- 工单类型创建后不可修改。
- 列表列为序号、提出人、类型、标题、状态、优先级、责任人和计划完成时间。
- 类型使用 `REQ` 或 `BUG` 标签展示。
- 标题单行省略，悬停显示完整标题；列表不展示正文或评论摘要。
- 提出人和责任人优先展示用户显示名，没有显示名时展示用户名。
- `PENDING` 和 `REJECTED` 的优先级、责任人和计划完成时间为空。
- `COMPLETED` 保留接受时设置的优先级、责任人和计划完成时间。
- `REJECTED` 只保存拒绝理由，不进行责任人分派。
- `COMPLETED` 额外保存系统自动写入的实际完成时间。
- 使用共享筛选面板，默认不带筛选。
- 筛选项为序号、提出人、标题、类型、状态、优先级和责任人。
- 提出人、标题和责任人使用大小写不敏感的文本模糊匹配；类型、状态和优先级按枚举精确匹配。
- 多个筛选条件支持选择 AND 或 OR。
- 未填写的筛选项不参与 AND/OR 组合。
- 优先级筛选提供显式“未设置”选项。
- 责任人和提出人不支持筛选“未设置”。
- 列表默认按工单 ID 倒序。
- 列表使用服务端分页，每页固定 50 条，不提供每页数量选择。
- 筛选条件变化或重置后回到第 1 页。
- 分页总数为应用当前筛选条件后的工单总数。

### 工单详情

- 工单详情使用可分享 URL `/tickets/<id>`。
- 详情展示工单内容、提交人、状态、处理字段、拒绝理由、创建更新时间、实际完成时间和评论。
- 详情分别展示创建时间和最后更新时间；新增评论不更新工单的最后更新时间。
- 正文和评论按纯文本保留换行并自动折行，不折叠或提供“展开全文”状态。
- `PENDING` 状态下，提交人可以在详情页打开编辑弹窗修改标题和正文；编辑复用提交弹窗。
- `PENDING` 状态下，`ADMIN` 可以打开接受弹窗，一次填写优先级、责任人和计划完成时间；
  确认后原子写入处理字段并转为 `ACCEPTED`。
- `PENDING` 状态下，`ADMIN` 可以打开拒绝弹窗，填写拒绝理由后转为 `REJECTED`。
- `ACCEPTED` 状态下，`ADMIN` 可以编辑优先级、责任人和计划完成时间。
- 编辑处理信息采用部分更新，请求至少包含一个修改字段，不要求每次重填全部处理字段。
- 后续调整计划完成时间时不限制必须晚于当前时间；设置为过去时间后按现有规则派生显示“已逾期”。
- `ACCEPTED` 状态下，`ADMIN` 可以确认标记完成；完成动作不要求单独说明，需要说明时使用评论。
- 列表只负责浏览和筛选；编辑内容、接受、拒绝、调整处理字段、完成和评论均在详情页操作。

## 并发与重复提交

- 后端在接受、拒绝、完成或编辑时重新校验当前状态和权限。
- 多个管理员同时处理同一工单时，第一个有效状态转换成功，后续冲突返回 `409 Conflict`。
- 前端遇到 `409 Conflict` 时提示工单已更新，并重新读取详情。
- 权限不足返回 `403 Forbidden`；责任人无效、接受时计划完成时间不在未来等业务输入错误返回
  `400 Bad Request`。
- 同一状态内并发修改标题、正文或处理字段时采用最后写入者覆盖。
- 提交工单和评论不使用 `Idempotency-Key`；前端请求期间禁用对应提交按钮。
- 不增加业务版本号或额外乐观锁字段。

## 输入安全

- 标题、正文、拒绝理由和评论以原始纯文本保存到 PostgreSQL。
- 后端使用 SQLAlchemy 参数化查询和 Pydantic 字段校验，不拼接用户输入生成 SQL。
- 前端使用 Vue 普通文本插值或组件文本属性展示用户输入，禁止使用 `v-html`。
- 不支持 HTML、Markdown 或富文本，不引入额外 HTML 清洗库。
- 包含 `<script>`、引号、分号或 SQL 关键字的合法文本必须能够正常保存和检索，但不能被执行，
  也不能改变查询结构。

## API

```text
GET    /api/v1/tickets
POST   /api/v1/tickets
GET    /api/v1/tickets/{id}
PATCH  /api/v1/tickets/{id}
POST   /api/v1/tickets/{id}/accept
POST   /api/v1/tickets/{id}/reject
PATCH  /api/v1/tickets/{id}/handling
POST   /api/v1/tickets/{id}/complete
POST   /api/v1/tickets/{id}/comments
```

- `PATCH /tickets/{id}` 只修改标题和正文，并执行提交人及 `PENDING` 状态校验。
- 接受、拒绝和完成使用独立动作端点，按当前状态执行单向转换。
- `PATCH /tickets/{id}/handling` 只允许 `ADMIN` 在 `ACCEPTED` 状态调整优先级、责任人和计划完成时间。
- 工单详情响应包含按创建时间正序排列的全部评论，不提供独立评论列表接口。
- 列表请求只接收从 `1` 开始的 `page`；后端每页固定返回 50 条。
- 分页响应包含 `items`、`total`、`page` 和固定值 `50` 的 `page_size`。
- 页码超过最后一页时返回空 `items`，不自动改写页码。
